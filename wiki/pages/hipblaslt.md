# hipBLASLt

AMD's extended BLAS library providing high-performance GEMM with flexible APIs, fused epilogues, and multiple kernel selection strategies including [[origami]] + [[stream-k]].

## Repository

[GitHub: ROCm/hipBLASLt](https://github.com/ROCm/hipBLASLt) | [Docs](https://rocm.docs.amd.com/projects/hipBLASLt/en/latest/)

## Core Operation

```
D = Activation(α × op(A) × op(B) + β × op(C) + bias)
```

Activations: GELU, ReLU, Swish/SiLU, Clamp — fused into the GEMM kernel epilogue.

## Data Types

Extensive mixed-precision support:

| Input | Compute | Output | Architecture |
|-------|---------|--------|--------------|
| FP8 (E4M3 FNUZ) | FP32 | FP16/BF16/FP32 | gfx942 |
| FP8 (E4M3) | FP32 | FP16/BF16/FP32 | gfx950, gfx12 |
| FP4 (E2M1) | FP32 | FP16/BF16 | gfx950 |
| FP6 (E2M3/E3M2) | FP32 | FP16/BF16 | gfx950 |
| FP16/BF16 | FP32 | FP16/BF16/FP32 | All |
| FP32 | FP32 | FP32 | All |
| INT8 | INT32 | INT32 | All |

Block scaling: `VEC32_UE8M0` (per-32-element), `VEC16_UE4M3` (per-16-element), outer vector scaling.

## Kernel Selection

### Three-Source Selection
1. **Standard grid** — pre-tuned kernels for known problem sizes
2. **Free-size library** — general-purpose kernels
3. **Origami + Stream-K library** — analytical model selection

Controlled via `TENSILE_SOLUTION_SELECTION_METHOD`:
- `0` — standard heuristic (no Stream-K)
- `2` — Origami + Stream-K enabled

On MI350: Origami + Stream-K is the **only** strategy.

### Tuning Approaches
1. **Offline** (`find_exact.py`) — exhaustive search for specific shapes, outputs YAML
2. **Online** (PyTorch TunableOp) — runtime benchmarking of all compatible solutions
3. **TensileLite** — generates new kernels extending the pool

### Tuning API
```
getAllAlgos() → isAlgoSupported() → algoGetHeuristic() → initialize() → run()
```

## Controls for Concurrent Execution

Critical for [[compute-comm-overlap]]:

```bash
# Limit GEMM to N CUs (leave rest for communication)
export TENSILE_STREAMK_MAX_CUS=272

# Fix workgroup count (prevents GEMM from monopolizing GPU)
export TENSILE_STREAMK_FIXED_GRID=64

# Grid sizing mode (6 = auto-optimal)
export TENSILE_STREAMK_DYNAMIC_GRID=6
```

These allow hipBLASLt to cooperate with concurrent [[rccl]] operations.

## Epilogue Operations

Extensive fused post-GEMM operations:
- Bias addition (broadcast)
- Activation: GELU, ReLU, Swish, Clamp
- Gradient operations: dGELU, bias gradient
- Auxiliary output for backward pass
- Per-matrix scaling (A, B, C, D, AUX)

## Grouped GEMM

Supports batches of independent GEMM problems with different sizes. `UserArguments` enables device-side argument updates — a prior GPU kernel can update GEMM parameters without host-device sync.

## Backend: Tensile / TensileLite

hipBLASLt kernels are generated by Tensile, AMD's GEMM code generator. TensileLite is the runtime component that handles:
- Kernel argument marshalling
- SplitK decomposition (splitting K across CUs for better utilization)
- Workspace allocation for partial results
- Grid dispatch

## Relationship to This Project

hipBLASLt is the production GEMM library that would consume communication-aware kernel selection from [[origami]]. The integration path:
1. Origami selects GEMM config aware of concurrent communication
2. hipBLASLt uses `TENSILE_STREAMK_MAX_CUS` to limit CU usage
3. [[rccl]] runs on remaining CUs or DMA engines

See [[codesign-rccl-hipblaslt]].
